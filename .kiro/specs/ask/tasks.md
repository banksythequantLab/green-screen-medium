# Implementation Plan: ask

## Overview

Build Ask as described in `requirements.md` and `design.md` in this folder: `POST /ask`, the package `greenscreen/publisher/ask/`, the `GS_ENABLE_ASK` / `GS_LLM_*` / `GS_ASK_*` settings, a second in-process MCP `Server` with transport `ask`, and an Ask panel on the console page. The work has two halves with a checkpoint between them. Tasks 1 to 3, 6 and 7 are done (their boxes stay checked). On 2026-11-20 task 10 was added after the reviewer's real run on Linux (Finding 13 of the requirements: a depth check that depended on the Python version, an off-topic question answered from outside knowledge, and Markdown asterisks in an answer). Run order now: task 10 (10.1 to 10.4, server side) FIRST, then tasks 4, 5, 8 and 9 (page, final run, amendments, final run), then the final report. Earlier run order, kept as history: tasks 1, 2 and 3, then tasks 6 and 7, then STOP. Tasks 1 and 2 finish the whole server side against a fake model adapter and have it green, including the five property tests. Task 3 is a report checkpoint that does not stop the executor. Tasks 6 and 7 apply the amendments to the server side and end with the report that the reviewer reads (task 7 is the STOP). Task 4 is the page, task 5 the final run, task 8 the page amendments, task 9 the final run for the amendments. The section "Reviewer-only items" lists what the executor does not run.

Production files touched: `greenscreen/publisher/config.py`, `app.py`, `rest.py`, `mcp_server.py`, `cli.py`, the new package `greenscreen/publisher/ask/` (six modules), `.env.example`, and the console files `index.html`, `console.css`, `console.js`, `snippets.js`, `codes.json`. Not touched: `calls.py`, `registry.py`, `vault.py`, `auth.py`, `console/__init__.py`, `pyproject.toml`, the Flow runtime, the Connector, any bundled Flow, `.kiro/steering`. Every path is repo-relative. The executor works on Windows with Python 3.11.9. Every task states: no live host, no real model, no browser; Windows.

On 2026-11-19, at the reviewer's request, every checkbox in this file was reset to unchecked. The text of tasks 1 to 5 still says they were executed before the amendments; read that as history, and let the reviewer decide which tasks to run again.

### Rules for every task

- DO NOT COMMIT and do not stage anything. Leave every change in the working tree. The reviewer commits.
- No secret is printed or written: no `GS_API_KEY`, `GS_LLM_API_KEY`, `TK5_PASSWORD`, `TK5_USERNAME`, host address or Bound_Value in code, tests, logs, assertion messages, notes or spec text. Test keys are generated per test and never written to a file. No spec or doc line starts with an assignment to `GS_API_KEY` or a `GS_BIND_` variable.
- No new dependency. `pyproject.toml` stays unchanged (`dependencies`, extras, `package-data`, `[build-system]`). `httpx2` is used undeclared and guarded by `tests/unit/test_ask_pin.py` (Decision 6). No framework, no build step, no CDN, no external font, script or image.
- Stop and report a production defect found outside the files named in the Overview. Do not fix it silently.
- Existing tests keep passing, unmodified, with exactly these flagged edits: `tests/unit/test_console_codes.py` (task 4.1) and `tests/unit/test_console_assets.py` (task 4.6, the allowed-path tuple gains `"/ask"`). `tests/unit/test_console_seance.py` is NOT edited: the design shows that a separate `.has-ask .seance-art-wrap` rule passes every scan in it. If any other existing test fails, stop and report the test and the cause; never edit it (Requirement 14.4).
- No task needs the live host, a real model, a real network or a browser. Tests use the Fake_Host, the `FakeAdapter`, `httpx2.MockTransport`, static files and a raw ASGI scope. The `no_network` fixture is autouse in every Ask test file.
- Node is needed for page tests. Prepend it for the shell: `$env:Path = "C:\Program Files\nodejs;" + $env:Path`, then record `node --version`. Node tests skip with the fixed reason `node is not on PATH; the Snippets_Module was not executed` when it is absent.
- Library documentation: before any task that writes code using a library API, re-check that API's row in the design's "Library documentation checks" table and the dated lines task 1.1 appended. If the installed version differs from the recorded one, or the row or the check is missing, read the page again and append a dated line (page, version, date) to that section of `design.md`. Tasks that do this say so.
- Static scans over `greenscreen/publisher/**/*.py` apply to the new modules: no `os.environ` or `getenv` outside `cli.py` and `config.py`; no `print(` without `file=sys.stderr`; no `.exception(` and no `exc_info`; the whole word `cancelled` only in `calls.py` (write `canceled`, `cancellation` or `cancelled_caught`); no identifier, attribute, argument or import name containing `cache` (the keyword `cache=None` in a call is allowed); no string constant that looks like an environment name and holds `PASSWORD`, `PASSWD`, `USERNAME`, `SECRET`, `TOKEN` or `CREDENTIAL`.
- Page scans: no `innerHTML` family, no `console.` call, `summary` only in the allowed forms of `console.js` and nowhere in `snippets.js`, no parameter name containing `key` in `snippets.js`, no scroll call anywhere, text nodes only.
- Every task is required. Nothing is marked optional with `*`. Property tests are sub-tasks of the work they test (Properties 1 to 5 of `design.md`, one `@given` test each, `max_examples` at least 100, first line `# Feature: ask, Property N: <title>`).
- Python version: the executor runs everything on 3.11.9. Python 3.12 to 3.14 are reviewer items.
- `.kiro/steering` is never edited. `.kiro` is never git-ignored.
